# docs/seminar — 아키텍처 세미나 자료

슬라이드 27장짜리 단일 HTML 덱이 두 벌 있다. 외부 의존은 Google Fonts 하나뿐이고,
참조하는 소스 코드는 파일 안에 스냅샷으로 심겨 있다. **파일 하나만 있으면 어디서든 그대로 동작한다.**

| 파일 | 무엇 |
|---|---|
| `swtp-platform-아키텍처-세미나-v2.html` | **발표용.** 문체와 구성을 다시 쓴 판 |
| `swtp-platform-아키텍처-세미나.html` | 최초판. 대조용으로 남겨 둔다 |

두 파일은 CSS·JS·SVG 도면·소스 스냅샷이 같고 **본문 텍스트만 다르다.**
아래 설명은 양쪽에 그대로 적용되므로 파일명만 바꿔 읽으면 된다.

## 여는 방법

### 기본 — 파일 더블클릭 (`file://`)

서버도 IDE도 필요 없다. 소스 참조를 클릭하면 심어 둔 스냅샷에서 코드가 펼쳐지고,
코드 뷰어 상단에 `스냅샷 · <날짜>` 배지가 붙는다.

USB·메신저로 이 HTML 파일 하나만 넘겨도 코드 인라인까지 똑같이 된다 — 리포지토리가 없어도 된다.

### 발표 중 리포지토리 최신 내용을 봐야 할 때 — 로컬 정적 서버

```bash
cd C:\project\swtp-platform          # 반드시 리포지토리 루트에서
python -m http.server 8000
```

→ `http://localhost:8000/docs/seminar/swtp-platform-아키텍처-세미나.html`

`http(s)://` 로 열면 스냅샷 대신 `fetch()` 로 **리포지토리의 현재 파일**을 읽는다(배지가 `리포지토리 현재`).
읽기에 실패하면 스냅샷으로 조용히 되돌아간다.

**루트에서 띄워야 한다.** `docs/seminar` 안에서 띄우면 상위 경로(`../../build-logic/...`)에
접근하지 못해 fetch 가 전부 실패하고 스냅샷 폴백으로 떨어진다.

IntelliJ 로 여는 것도 같은 원리다 — IDE 내부 웹서버(`localhost:63342`)가 서빙하므로 `http://` 가 된다.

| 키 | 동작 |
|---|---|
| `←` `→` `Space` | 슬라이드 이동 (빈 곳 클릭도 다음 장) |
| `O` | 전체 목차 패널 |
| `P` | 인쇄 — PDF로 저장하면 슬라이드 1장이 1페이지 |
| `T` | 라이트 / 다크 전환 |
| `Esc` | 열린 패널 닫기 |
| 코드 뷰어에서 `I` | 해당 파일을 IntelliJ에서 그 줄로 열기 |

## 소스 참조

본문의 점선 밑줄 + `↗` 표기는 **리포지토리의 실제 파일**로 이어진다.
슬라이드 마크업에 링크를 손으로 심지 않고, HTML 하단 스크립트의 `SRC` 맵이
"화면에 보이는 문자열 → 파일 경로:줄" 대응을 갖는다.

참조를 추가·수정할 때는 그 맵만 고친다.

```js
var SRC = {
  'swtp.spring-boot-app': ['build-logic/src/main/groovy/swtp.spring-boot-app.gradle', 24],
  ...
};
```

### 스냅샷 갱신 — `SRC` 맵이나 참조된 파일이 바뀌면 반드시 다시 돌린다

```bash
node docs/seminar/embed-sources.mjs                                       # 최초판
node docs/seminar/embed-sources.mjs swtp-platform-아키텍처-세미나-v2.html    # 발표용
```

인자를 주지 않으면 최초판을 갱신한다. **덱이 두 벌이므로 두 번 돌려야 한다** —
한쪽만 돌리면 그쪽 배지 날짜만 바뀌고 다른 쪽은 낡은 코드를 계속 보여 준다.

`embed-sources.mjs` 가 `SRC` 맵에서 대상 목록을 뽑아 파일 전문을 읽고,
HTML 하단의 `<!-- SRCDUMP:BEGIN -->` ~ `<!-- SRCDUMP:END -->` 블록을 갈아끼운다.
대상 목록의 진실 원천은 `SRC` 맵 하나이므로 스크립트에 경로를 따로 적지 않는다.

- 이 블록은 **손으로 고치지 않는다.** 마커 사이만 교체되므로 나머지 서식은 보존된다.
- 같은 날 여러 번 돌려도 결과가 같다(멱등). `generated` 는 날짜 단위다.
- 갱신을 잊으면 `file://` 로 열었을 때 **낡은 코드**가 보인다. 배지의 날짜로 확인할 수 있다.
- `SRC` 에 새 파일을 넣고 스크립트를 안 돌리면 그 참조만 안내 문구로 떨어진다 — 나머지는 정상 동작한다.

**리포지토리를 다른 경로에 두면 `REPO_ABS` 한 줄을 고친다** — IDE 딥링크(`idea://`, `vscode://`)에만
쓰이는 절대 경로다. 브라우저 링크와 코드 인라인은 상대 경로라 영향이 없다.

## 파일을 옮길 때

`REPO_REL = '../../'` 이 리포지토리 루트를 가리킨다. 이 파일이 `docs/seminar/`에 있다는 전제이므로,
디렉토리 깊이가 바뀌면 이 값을 함께 고친다.
