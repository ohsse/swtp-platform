## 토의 결론

네 블로커의 뿌리는 하나다 — **"어디에 한 벌만 두는가"를 정해 놓고 실제 파일에서 지키지 않았다.** B1은 절차·데이터 복제, B2·B3은 "Plan mode로 강제"라 적어 놓고 하네스 동작을 확인하지 않은 채 안내 문장으로 구현, B4는 보고 의무를 정해 놓고 보고하지 않음. 처방 — 각 내용의 단일 출처를 아래 표로 못박고 나머지는 참조로 바꾼다. 강제는 하네스가 실제로 제공하는 수단으로 바꾼다.

이로써 **plan.md 결정 1의 경계 서술("`/work`는 모드 진입과 파일 전이를 소유")이 바뀐다** — 파일 전이의 단일 출처는 `worklog.md`다. plan.md는 동결이므로 고치지 않고 complete.md 「알려진 한계」에 적는다.

### Plan mode — 강제 수단 교체 (B3) 와 `/work` 진입 (B2)

- `/ask`·`/explain` 프론트매터에 `disallowed-tools: Edit, Write, NotebookEdit`. 0절은 "Plan mode 표시가 없으면 **`EnterPlanMode` 도구를 호출**한다". 도구 호출이 1차, 프론트매터 차단이 2차. 안내 문장 폐기.
- `/work` 1절: "Plan mode가 켜져 있으면 plan.md를 쓸 수 없다. 끄고 다시 불러 달라고 안내하고 **멈춘다**." 게이트 이전 무수정 보장은 Plan mode가 아니라 **절차**(승인 전에는 `docs/<slug>/`만 쓴다) — complete.md 알려진 한계에 명시.
- task.md 「번호 없음 = 미승인」의 "첫 사례의 예외"를 "Plan mode 안에서 승인되면 docs/ 밖에서 승인이 끝나 번호 없는 단계를 건너뛴다. `/work`로 들어오면 전이표대로 간다"로 정정.

### CLAUDE.md 「갱신 규칙」 충돌 (B4)

task.md 변경 없음 행에 충돌 사실을 덧붙이고, complete.md 「다음 단계」에 `/claude-md-sync` 대상으로 올린다. CLAUDE.md 자체는 손대지 않는다.
