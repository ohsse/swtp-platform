# docs 01 — plan: 진행 컨벤션 3모드와 단계별 작업일지

- 일자: 2026-10-07
- 상태: 승인됨 (2026-10-07) — 이후 동결

## 발단

사용자가 프로젝트 진행 방식을 "대화 모드 3종 + 단계별 작업일지"로 정형화하자고 제안했다. 제안의 골자는 ① 단순질의·설명·계획및착수 세 모드를 구분하고 앞의 둘은 일체 수정하지 않는다 ② 작업일지를 `docs/{slug}/{plan|task|review|recycle|complete}.md`로 두고 주제·작업일자·토의내용·작업내용·결과 5필드를 갖는다 ③ 리뷰에서 블로커가 나면 토의 후 recycle 또는 complete로 간다.

기존에는 `/step` 스킬(2026-08-24 확정)이 같은 자리를 맡고 있었다 — 토론 → 게이트 → 구현 → 리뷰를 한 축으로, 산출물은 **단일 파일** `NN-주제.md` 하나. 그 관례로 11개 문서가 쌓였고 마지막 완성형이 `apps/gateway/docs/02`다. 따라서 이 작업은 백지 설계가 아니라 **기존 규약과 새 제안의 병합**이다.

조회 결과 드러난 것: `/step`은 "절차는 스킬(전역)에, 경로는 리포에"를 선언해 놓고 실제로는 swtp 불변식 7개 표·전문가 판정표·문서 경로 표를 스킬 본문에 하드코딩하고 있었다. 다른 리포에서 `/step`을 쓰면 swtp 불변식을 검사하게 되는 결함이다.

## 검토 관점

전문가 소환 **0명**. 코드·스키마·토픽·compose 어느 것도 바뀌지 않고(판정표상 모든 행이 해당 없음), 대상이 "우리가 어떻게 일할 것인가"라 배타적 입력으로 자를 외부 지식원이 없다. 대신 사용자와 1:1로 4회차 질의응답(총 11개 결정)을 돌았다. 갈린 의견은 없었다 — 모든 항목에서 사용자가 권고안을 택했다.

단, 토의 중 AI 쪽이 제시한 **사실 확인 1건**이 결정을 좌우했다: `.claude/rules/*.md`가 Claude Code 공식 기능인지(아니면 정형화 수단 분배 전체가 무너진다). 별도 에이전트로 공식 문서(https://code.claude.com/docs/en/memory.md)를 확인해 지원됨을 확정한 뒤 결정 9·11을 내렸다.

### 결정 사이의 충돌 하나와 해소

4("승인 시 부여")와 5("docs/에 바로")를 합치면 승인 전 디렉토리에는 번호가 없어야 한다. 그래서 **번호 없음 = 미승인**을 디렉토리명이 갖는다. 승인 시 `git mv <slug> NN-<slug>`, 기각 시 `git mv <slug> 미착수/<slug>`. `ls`만으로 미승인 작업이 보이고 번호 구멍도 안 생긴다.

### 단일 파일 → 분할의 근거

`/step` 6절은 "새 파일을 만들지 않는다 — 두 문서가 생기면 어긋나고, 어긋난 틈에서 미완이 완료로 세탁된다"고 적었다. 그 우려는 유효하지만 처방이 틀렸다. gateway 02에서 세탁(함정 기록 7, 조작된 실측 출력)을 잡은 것은 파일이 하나여서가 아니라 **fresh 리뷰어가 주장과 출력을 대조했기** 때문이다. 세탁 방지는 파일 수가 아니라 **마지막 산출물이 앞 산출물을 대조하느냐**에 달려 있다. 그래서 분할하되 complete.md가 review.md의 블로커를 번호째 전부 인용하도록 강제한다.

분할의 이점은 plan.md **동결**이다. 단일 파일은 구현 중 「결정」 절 정정을 허용해 "원래 뭘 하기로 했었나"가 지워졌다(gateway 02 함정 기록 5가 "「변경 내역」이 처음에 ~라고 적어 사실보다 앞서 있었다"고 자백하지만 그 '처음'은 git에만 남는다). plan.md가 동결이면 검증 기준이 구현에 맞춰 내려갈 통로 자체가 막힌다.

## 검증 방법 — 착수 전 확정

1. **구조**: `docs/01-…/`에 README·plan·task·review·complete가 있고 complete.md의 블로커 대조표가 review.md의 블로커 번호를 전부 포함한다.
2. **`/step` 이식성**: `/step` 본문에 `swtp`·불변식 표·판정표가 남아 있지 않다(grep 0건). rules 파일이 없는 리포에서 호출하면 "사용자에게 묻는다" 경로가 명시되어 있다.
3. **rules 크기**: 세 파일 합계 200행 이내(세션마다 무조건 로드되므로).
4. **스킬 동작**: fresh 에이전트가 `/work <가상 주제>`를 따랐을 때 번호 없는 `<slug>/`에 README·plan.md만 만들고 코드를 건드리지 않으며 게이트에서 멈춘다. fresh 에이전트가 `/explain`을 따랐을 때 코드보다 작업일지를 먼저 읽는다.
5. **기존 문서 무변경**: `git status`에서 `apps/*/docs/`·`infrastructure/docs/`·`starters/docs/`·`docs/scaffold/`에 변경이 없다.
6. **리뷰**: 중량(횡단 + 기존 결정 뒤집기). 전용 리뷰어를 fresh로 띄워 산출물을 이 plan.md 대비 3축으로 대조한다.
